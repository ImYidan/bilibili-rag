## 案例 1：总结收藏夹

- **日期：** 2026-11-08
- **系统版本：** bilibili-rag 原版（未改造），qwen-plus
- **问题：** 总结一下我的收藏夹（大意）
- **路由：** db_content（问题包含"总结"，规则路由直接分到这条路线，不经过检索）
- **数据情况：** 测试收藏夹里的视频语音识别失败，数据库正文只有"标题 + 简介"

**系统回答（节选）：**

> 这个收藏夹聚焦于技术学习与高效工具使用……覆盖 AI 前沿、工程实践、学习工具和信息获取渠道四大方向。
>
> 《时序预测相关最新论文总结综述（24.02~24.04）》聚焦前沿动态：梳理 2024 年初时序预测领域（如 Time-Series Foundation Models、多变量预测、长程建模等）关键进展……
>
> 整体特点提炼：（表格，重复前文内容）
>
> 一句话总结：……体现出清晰的学习路径规划与强执行力。
>
> 如需我帮你进一步：梳理思维导图 / 提取 Top 5 新方法简评 / 整理速查表……

**问题分析：**

| 问题类型 | 表现 |
|---|---|
| 内容来源错误 | 只复述了视频简介（"附带飞书图文教程""链接明确标注"等明显来自简介），没有视频本身的内容 |
| 疑似编造 | "如 Time-Series Foundation Models、多变量预测、长程建模等"，待核对简介中是否出现；若没有，属于模型根据标题猜测，违反忠实度 |
| 评价用户 | "理性批判意识""强执行力"等，与问题无关 |
| 格式冗余 | 表情符号、用表格重复前文、结尾推销后续服务；输出越长越慢 |
| 问题本身价值低 | 收藏夹主题混杂（Transformer、计算器、Chrome），整体总结意义不大 |

**原因定位：**

1. **数据：** 语音识别失败后静默退回"标题 + 简介"，且 is_processed 仍为 True，界面看不出问题（content_fetcher.fetch_content）。
2. **路由：** 关键词规则把含"总结"的问题送到 db_content，把所有视频正文塞进提示词，不做检索（chat.py · _route_with_rules）。
3. **提示词：** _build_db_summary_messages 只要求"提炼重点、结构清晰、必要时引用标题"，没有约束：只用给定内容、内容不足时说明、长度、不评价用户、不推销。

**用户观察：** 细问具体内容时回答质量不错；问题在于不了解视频内容时不知道该问什么。由此引出"引导提问"需求（入库时为每个视频生成 3 到 5 个可回答的问题）。
